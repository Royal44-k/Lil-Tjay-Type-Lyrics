# Suno 制作与筛选

沿用本对话已确定的分工：本包给出词曲与制作输入，用户在自己的浏览器中生成演唱与音频。本轮未操作账户、消费额度或编造试听结果。

## 导入

使用 SUNO-PASTEBOOK.md，每首的 Title / Style / Exclude / Lyrics 分别放到对应字段。歌词框只含歌词与简短方括号标签；中文分析、BPM 表和角色代号不放进去。参考 [Suno 自定义歌词说明](https://help.suno.com/en/articles/2415873) 与 [Exclude 说明](https://help.suno.com/en/articles/3161921)。

2026-09-18 核查的 [v6 FAQ](https://help.suno.com/en/articles/13924481) 将 v6 定位于较明确目标、v6-wild 定位于探索，可用模型依方案而定。优先使用账户可用的稳定模型；若界面有 Variety，设为 0 可减少风格标签被改写。Max Mode 是更耗额度的可选项，先比较普通候选再决定是否需要。具体界面以实际账户为准。

本包没有把模型、随机性或数值滑块当成声音质量保证。精确节拍、音符、人声角色和相同 take 都要另行检查。

## 第一轮候选

1. **01 ONE OF ONE**：先选出自然男声与清楚的标题动机。听第一轮 Hook、第一段主歌及 what if 句，三处都成立才作为声音基准。
2. **03 DON'T MAKE IT COOL**：检查男声羞涩与女声直接的区别，以及较密主歌能否听清。优先修咬字，不给密度问题加更多混响。
3. **05 WEAR IT OUT**：验证克制情绪，不接受每行都哭腔或高潮化。外套、牛奶和口袋里的旧票是必要叙事信息。
4. **06 GOOD ON ME**：验证高能量下仍听得懂、能记住的 Hook；若 saw 遮住辅音，先删减合成器。
5. 再做 02、04、07，并按专辑顺序回听。候选优先级不改变最终曲序。

每首至少比较实际生成的一组候选，再记录选择；本文件没有虚构已生成次数或已通过评分。候选 ID 使用 DBE01-A01 这类稳定编号，日志记 URL、模型、提示版本和真实观察。

## 精确旋律与采样的两条路径

**文本探索**：直接使用歌词和 Style，获得独立草样。若输出没有复现 MIDI，可以作为另一旋律候选，记录差异后判断，不假称严格执行了本稿。

**按本稿实现**：先把 HOOK-GUIDE.mid / 源谱用合适音源渲染，或录真人 guide，得到实际音频后再作为参考。MIDI/MusicXML 本身不是这里假定 Suno 可以直接读取的上传文件。v6 官方说明支持音频参考与局部修改，但仍需检查结果。严格的同一采样复用可在后期工程中使用同一 WAV 完成。

首尾三音变奏要比较音高与相对起音：01 G#–B–C#，07 Ab–C–Db。若生成结果无法控制，可先保持七首各自好听，再在后期补录共同动机；实际完成前，在日志中保留“母题未实现”。

## 声部与结构修正

03：Verse 1 男，Verse 2 女，Bridge 前两行男后两行女，Post 女；最后 Hook 为小规模二重唱。

06：Verse 1 男，Verse 2 女；Bridge 男/女/男/女；Outro 女。女声不用模仿任何真实艺人，也不必提高尖锐度证明角色不同。

标签只是方向，不是硬性路由。串位时优先保留最好的段落，再局部编辑或分段制作后拼接。REFINEMENT.txt 提供针对性英文修改提示。一次只改变一个主要变量，保留原候选以便比较。

真实结构变长或变短时，更新实际时间和歌词对齐。计划 18:04 不应迫使自然演唱抢词；整曲移调时记录新调性，所有关联器乐一起调整。

## 选择 keeper

第一遍不看歌词，记住能复唱的片段和情绪；第二遍对照文本找漏字、错字、重音和角色；第三遍听低频、器乐与人声是否争位。候选比较先尽量匹配感知响度。

评分可采用本项目的 1–5 分：Hook 识别、咬字、情绪可信、声部分工、编曲空间。分数不是行业认证，必须配具体理由。最关键的缺陷优先修，不因总分高而放过整段歌词漏唱。

将结果写入 GENERATION-LOG.csv；有成对假设比较时写入 LEARNING-LOG.csv。确认后再进入 AUDIO-QC.csv 的实测与混音阶段。
