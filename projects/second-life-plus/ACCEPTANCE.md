# SECOND LIFE+ — 交付与验收规范

## 适用阶段

**当前目标：可进入 Suno 制作的预制作交付。当前不等于发行级音频验收。**

“主流 hip-hop 行业标准”不是一套统一的歌词行数、BPM 或 LUFS 数字。本项目将其落实为可追溯的版本、清楚的创作与录音分工、真实署名和素材来源、可复现文件、逐项音频 QC，以及分发平台的实际要求。创作检查采用本项目标准；平台技术建议另列来源。

## A. 本轮预制作交付验收

| 项目 | 本项目的通过条件 | 证据 / 当前范围 |
|---|---|---|
| 曲目范围 | 恰好 3 remix + 4 new + 1 retained | album.json / TRACK-METADATA.csv |
| 原曲保留 | SECOND LIFE 的歌词、提示词、排除项、Hook MIDI、逐音 CSV、段落 CSV 与旧版逐字节一致 | PRESERVATION.json，六文件 SHA-256 |
| Remix 身份 | 保留指定动机的音程和相对节奏，同时重写主要叙事与主歌 | QC-REPORT.json；6/9/7 音核对；FAST FORWARD +3 半音 |
| 叙事变化 | 各 remix 的新角色提供新的信息、矛盾或回答 | ALBUM-DIRECTION.md / 各曲 PRODUCTION.md |
| 完整歌词 | 八首完整展开重复段落，无“副歌同上” | SONGBOOK.md / LYRICS.txt |
| 演唱分配 | 每一行有角色与小节份额；Bridge 的换人顺序明确 | VOCAL-MAP.csv |
| 旋律 | 8 个 Hook guide；新七首含可编辑主旋律谱 | MIDI / CSV / MusicXML；只证明作曲资料存在，不证明唱得好 |

| 状态真实 | 没有伪造歌手、分成、Suno URL、试听结果、音频测量或发行代码 | 管理表保留待填字段；audio_exists=false / release_ready=false |

STYLE 的 1000 字符预算、180–650 的歌词词数校验是本包内部合理性检查，不宣称是 Suno 官方硬上限，也不替代听检。

## B. 歌词与演唱的 14 项审校

采用指定技能库的审校思路，并针对说唱作调整。书面结果可评审，演唱结果必须等音频。

| 检查项 | 本稿处理 | 音频阶段还需做什么 |
|---|---|---|
| 1 韵脚 | 标出主韵组、内部韵与有意的近韵，不把相同尾词当新韵 | 听尾字是否清楚、近韵是否自然 |
| 2 重音 | 标出标题及关键短语；Hook 音节已配音高 | 检查多音节词是否被强行重读 |
| 3 发音 | 记录 receipt、Ivory、Counterstep、quiet 等 | 按实际错误修最小拼写，不盲目把全词改成音标 |
| 4 POV | 多人物仅在标明的声部切换；相邻歌曲不强行同一人物 | 听众能否辨别谁在说话 |
| 5 时态 | 回忆与当下转折有语义依据 | 检查新增或漏唱造成的时间混乱 |
| 6 主歌推进 | 第二段必须增加事件或改变看法 | 是否变成“同一段唱两遍” |
| 7 细节 | 用动作、物件、对话承载情绪 | 细节是否被吞掉或改词 |
| 8 语法口语 | 避免为押韵倒装和不自然措辞 | 母语听感与实际发音复审 |
| 9 密度 | 快网格两小节一行、慢曲一小节一行 | 演唱是否需要吞字或喘不过气 |
| 10 段落 | 有明确差异，不让所有曲目同一模板 | 模型是否多唱、错序或提前结束 |
| 11 Hook | 每首独立识别词；remix 保留可验证的母动机 | 一遍后是否能哼出标题，属于听检而非书面保证 |
| 12 呼应 | 回收意象要改变含义，避免全部歌词都解释“第二次生命” | 是否过度重复或过度概念化 |
| 13 来源 | 虚构人物与真实研究分开；不引用参考曲歌词 | 新生成音频是否出现不需要的外来歌词或素材 |
| 14 提示词 | 用音色、奏法与结构描述声音，未写真实艺人名字 | 实际模型能否按方向执行 |

书面二次修订已处理的例子：IVORY HOURS 用葬礼后的动作明确叙事时间；SOFT LANDING 删掉连续两行相同的 there 收尾；LAST TRAIN 删除不自然的 chasing a ceiling；NO RECEIPT 调整工程师段的采访措辞。没有把这些改写冒称为母语歌手试唱验证。

## C. Suno 草样验收

各曲真实生成后，至少完成以下检查再选 keeper：

- 标题 Hook 可辨认，三个 remix 的动机与 guide 对照成立；移调允许整曲统一调整，并更新版本。
- 歌词无关键漏字、替换、意外重复或无法理解的连读；段落完整。
- 角色轮换符合该曲要求，或经分段编辑已解决。仅有同一声线唱完不自动满足多人物制作要求。
- 钢琴/提琴实际承担指定角色。持续的弦乐垫不能自动算作完成了“演奏采样重排”。
- 节拍与声部服务情绪；计划速度和调性与实际值分别记录，不能把提示值当实测值。
- 没有不必要的呼喊、口播标签、突兀尾切、明显水声、破音、糊字或采样接缝。
- 关闭播放后能否记住标题动机，可邀请听者做简短复述/哼唱；这是本项目听检办法，不是行业法规。
- 在同等感知响度下比较候选。GENERATION-LOG.csv 记录留用理由及需修问题，不能只填“好听”。

## D. 音频交付与发行前验收

这部分目前全部 **PENDING AUDIO / PENDING CREDITS**，不得盖已通过章。

### 录音与工程文件

- 保存原始下载、原始器乐/人声 take、剪辑版和最终版。不同版本使用稳定 Track ID 与递增版本号。
- 立体声主混音、伴奏版、主唱/和声、鼓、Bass、主要乐器与 FX stems 根据真实工程导出。所有 stems 使用共同起点、相同长度、同一采样率，保留必要尾音。
- Suno 分离得到的 stems 若有渗漏或伪影，如实标记，不能等同于原始隔离多轨。
- 优先保存真实原生分辨率的无损文件；新录音与混音工程可采用 24-bit PCM / 44.1 或 48 kHz 等合适规格。不要把 16-bit 文件补零或升采样后冒称原生高分辨率。Apple 的 Digital Masters 指南明确强调原生来源与避免无意义上采样。[Apple 官方指南](https://www.apple.com/apple-music/apple-digital-masters/docs/apple-digital-masters.pdf)

### 混音与母带

- 在实际音频上测量 LUFS-I、最大短时响度、dBTP、LRA、采样率、位深、时长，并填写 AUDIO-QC.csv。
- 检查非预期数字削波、刺耳齿音、808 遮挡、低频相位、声像中心、采样尾音和结尾截断。艺术性失真与非预期数字损坏分别判断。
- 耳机、近场或可靠主监听、小音箱/手机、单声道检查；不能只看频谱截图。
- 进行有损编码预览，检查编码后峰值与高频伪影。
- 保留曲目之间设计好的动态差异，不以“八首 LUFS 相同”替代专辑平衡。

Spotify 的官方建议是以 -14 LUFS-I 和低于 -1 dBTP 为优化目标；更响的 master 建议低于 -2 dBTP。它也解释了播放端归一化。本项目记录这些建议，不将 -14 当作所有 hip-hop 的唯一审美目标或全行业接收门槛；最终密度依据实际音乐、编码检查和分发要求确定。[Spotify 官方说明](https://support.spotify.com/au/artists/article/loudness-normalization/)

### 署名、版本与发行资料

- 确认主艺人、真正的客串、词曲作者、制作人、演奏者、录音/混音/母带工程师及约定分成；不得把角色代号或 AI 的虚构名字填进去。
- 填清每段 source 的实际来源、录音者/所有者、使用条件与确认文件；Suno 生成素材记录账户适用条件和生成记录。
- 正式歌词去掉制作标签，并按最终录音校对；时间同步歌词在实际音频定稿后制作。
- ISRC / UPC 由实际发行流程分配，不自行编造。IFPI 说明新的或实质改变的录音需要独立 ISRC；此处保留的只是旧词曲资产，不能凭相同歌名判定未来音频是不是同一录音。[IFPI](https://isrc.ifpi.org/why-use-isrc/when-to-assign)
- 曲名与 remix 版本名、明确内容标记、封面和音频版本在分发资料中一致。当前歌词没有脏话，生成后的临时 ad-lib 仍须复核。

## 最终签核记录

词曲 / A&R、制作、人声、混音、母带、署名与发行资料可由同一独立制作人承担，也可以由不同人员承担，但每个阶段必须有真实姓名、版本、日期、问题处理记录。模板已提供，当前未虚填签名或认证。
